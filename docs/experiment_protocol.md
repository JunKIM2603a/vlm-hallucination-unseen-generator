# Experiment Protocol

## Principle

The protocol must distinguish:

```text
hallucination generalization
        from
generator recognition / shortcut exploitation
```

A LOGO performance drop alone does **not** prove a generator-fingerprint mechanism.

## Stage 0 — provenance audit

Before training:
- identify the authoritative SHEEP release;
- verify per-sample generator identity;
- verify human-written vs machine-generated labels;
- inspect whether source image/prompt IDs repeat across generators;
- identify missing or ambiguous generator labels;
- record exclusions and final sample counts.

Recommended mapping schema:

```text
sample_id
source_id
image_id
prompt_id
generator_id
is_human
target_label
span_annotation
hallucination_type
split_eligibility
provenance_source
```

## Split definitions

### Random split

Requirements:
- deterministic seed;
- same eligible sample pool as LOGO whenever possible;
- group source-linked duplicates when required to prevent trivial leakage;
- preserve benchmark constraints.

### Leave-one-generator-out

For each generator `g`:

```text
test       = all eligible samples generated by g
train      = samples from all other generators
validation = train-side generators only
```

The held-out generator must not influence:
- hyperparameter selection;
- early stopping;
- threshold tuning;
- calibration;
- model selection.

## Minimum Decisive Experiment

Start with a simple text-only classifier.

Purpose:
- minimize engineering delay;
- establish whether an unseen-generator gap exists;
- avoid multimodal complexity before the central phenomenon is demonstrated.

Compare:
1. random split;
2. each LOGO holdout;
3. mean LOGO;
4. random-minus-LOGO gap.

Use multiple fixed seeds when runtime permits.

## H2 fingerprint tests

### Generator-ID probe

Train a lightweight probe for `generator_id` from:
- raw/text-derived features;
- frozen detector embedding;
- selected intermediate representations.

A successful probe shows generator information is encoded; it does not by itself prove causal use by the hallucination head.

### Association analysis

Test whether:
- higher generator-probe accuracy;
- greater representation separation;
- or specific generator pairs

are associated with larger LOGO drops.

### Stronger mechanism evidence

Reduce generator-identifying information through an intervention and test whether unseen-generator performance changes accordingly.

## Model families

### A. Text only
Text encoder/features → hallucination prediction.

### B. Frozen vision + text
Frozen visual representation + text representation → fusion head.

### C. Multimodal fusion
Joint multimodal representation → hallucination prediction.

## Generator-adversarial intervention

Shared representation `h` feeds:
- hallucination span/task head;
- hallucination type head;
- generator-ID adversarial head.

Objective:

```text
L = L_span + α L_type − β L_generator
```

Use a gradient reversal layer so the generator classifier minimizes its own loss while the shared encoder receives the reversed generator gradient.

Tune `α` and `β` using train-side data only.

## Metrics

Required families:
- character/span IoU;
- correlation;
- label-conditioned correlation;
- hallucination-type metric;
- per-generator score;
- random-vs-unseen-generator gap.

Before main runs, freeze for every metric:
- exact formula;
- aggregation level;
- empty-span handling;
- macro/micro averaging;
- uncertainty interval method.

## Statistical reporting

At minimum:
- point estimate for each split;
- per-generator LOGO result;
- mean LOGO;
- random-minus-LOGO gap;
- uncertainty interval where valid;
- seed variability when repeated training is used.

Do not treat the five generator holdouts as interchangeable IID samples without discussing heterogeneity.

## Confound checks

Where metadata permits, inspect:
- prompt distribution;
- image/source distribution;
- answer length;
- language;
- formatting;
- refusal style;
- lexical diversity;
- hallucination prevalence;
- hallucination-type prevalence.

## Experiment ledger

Every main run should record:

```text
run_id
date
git_commit
dataset_version
eligible_sample_hash
split_type
heldout_generator
seed
model
hyperparameters

```

## Stop / continue rule

- **GO:** repeated, practically meaningful random-vs-LOGO degradation.
- **CONDITIONAL GO:** large heterogeneity across held-out generators.
- **KILL:** no reliable provenance or negligible gap across all holdouts.
